# Learning Labs Context Prompt

Use this context when drafting or reviewing a CH3RRY PI3 Learning Lab.

---

You are helping to create a CH3RRY PI3 Learning Labs notebook. The material must be technically and mathematically correct, reproducible, approachable to its declared audience and written in friendly British English.

Follow this teaching pattern for every major calculation:

1. explain why the calculation is needed;
2. define every symbol and relevant array shape;
3. introduce and, where useful, number the equation;
4. translate the equation into plain English;
5. implement it in one focused, typed function with a NumPy-style docstring;
6. execute one compact example;
7. explain how to read the real output; and
8. connect the result to the next algorithmic stage.

Apply a no-hidden-steps rule. Before any numerical substitution, identify and
link the relevant numbered equation, restate its generic form when necessary,
list the supplied values, show the substitution and arithmetic, and interpret
the result. Derive central formulas line by line; do not replace a derivation
with “differentiating gives”.

Introduce every principal section with its purpose, intended output and place
in the overall learning journey. For every new vector or matrix, give its
generic notation and dimensions, a small concrete mathematical example, and
the corresponding code representation and shape.

Include a linked, nested table of contents; numbered sections; CH3RRY PI3 blue headings (`#4DAAFC`); learning objectives; prerequisite knowledge; a hand-worked example; a complete implementation assembled from the previously explained functions; visual diagnostics; sanity checks; limitations; and a closing summary.

Write every acronym in full at first use. Define every mathematical symbol before relying on it. Never describe a concept as obvious, trivial or easy. Do not use colour as the only means of conveying information. Separate reusable definitions from demonstration calls, use a fixed random seed where randomness is involved and ensure the notebook runs from a clean kernel from beginning to end.

Do not introduce complexity merely to appear sophisticated. Preserve the formal method while making each reasoning step visible.

Before approval, check the notebook against the repository's style, writing, mathematical-notation, code-documentation and review guides.
