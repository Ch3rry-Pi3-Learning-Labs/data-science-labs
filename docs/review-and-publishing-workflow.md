# Review and Publishing Workflow

## 1. Select and bound the topic

Define the intended audience, prerequisites, learning outcomes, practical value and explicit exclusions. A Learning Lab should answer a coherent learning need rather than attempt to cover an entire discipline.

## 2. Complete the planning brief

Use the notebook planning brief in `templates/`. Confirm the proposed structure, mathematics, dataset, visual outputs and completion criteria before substantial drafting.

## 3. Build from the template

Copy the reusable notebook template and retain its learning objectives, linked contents, modular development, worked example, checks and summary structure.

## 4. Technical and mathematical review

Confirm that:

- equations and derivations are correct;
- every symbol is defined;
- code implements the stated mathematics;
- outputs support the accompanying claims;
- numerical safeguards are appropriate; and
- limitations are stated honestly.

## 5. Educational and accessibility review

A technically capable non-specialist should review the notebook for unexplained jargon, hidden assumptions, excessive jumps, confusing outputs and inaccessible presentation.

## 6. Reproducibility check

Restart the kernel and execute every cell in order. Confirm that the notebook completes without errors and that outputs, figures, anchors and links render correctly.

## 7. Release review

Use the publication checklist. Confirm the title, filename, repository location, dependencies, description, licence position and any accompanying social or Discord material.

## 8. Publish and adapt

Publish the substantive notebook to GitHub first. Create platform-appropriate summaries for LinkedIn, Discord and the CH3RRY PI3 website without treating those summaries as substitutes for the notebook.

## 9. Learn and revise

Record production time, reader questions, completion problems, engagement and reuse opportunities. Apply those lessons to both the notebook and the house standards.
